LGT WIPI-C《失落的帝國2》漢化手記

發表於2026-08-30|更新於2026-09-07|塵封

前言

지크，早在 J2ME 時代，便由「大連玉衡」引進國內，取名為《失落的帝國》。

在同期的韓遊中，《失落的帝國》並無太多的競爭優勢；但其質量之硬，依然能夠把一眾國產 ARPG 打擊得顏面盡碎。

哈，扯遠了。這次我們要聊的，是大連玉衡未能代理的《지크2》。

在看到它的第一眼，我就決心要漢化它。

LGT 的 WIPI-C，在目前尚是一片混沌。不過也巧，我之前因為興趣，有過《鬼劍士》和《鬼泣》的 Hack 經驗。

這 WIPI 系統韓遊漢化的第一枚桂冠，就由我來摘得吧。

當然，私並非逆向工程師。逆向 Class 尚可，但面對二進位，就顯得黔驢技窮了。

現代操控 LLM 漢化最重要的思維，個人總結下來莫過於「斬草循根」。

斬草，即把原遊戲表層的文本渲染鏈路，替換為我們自己設計的中文渲染鏈路。

循根，即遵循原版遊戲對部分文本的特殊渲染邏輯，不自己額外實作一套。

這樣以此為基準，LLM 也很難在現有補丁上反覆 fallback、特判。整個工程會因此變得緊湊而嚴謹。

好了，讓我們開始吧。

準備工具

工欲善其事，必先利其器。

WIPI-C 雖然是 JAR 檔尾，但它的心臟卻是一個二進位塊（binary.mod）。

IDA Pro 9.3

binary.mod 是 ARM 32 小端塊，主要使用 Thumb 指令。

逆向追索核心邏輯的任務，便交給 IDA 這位行家吧。

IDA Pro MCP

過去逆向二進位仍需手動操控 IDA，向 LLM 解釋「這個函式從哪來」「那個地址又是誰」，實在麻煩。

現在可以讓它直接操控並閱讀 IDA 裡的函式、交叉引用和反編譯結果。

Hex

一般模型都會使用 bash 命令來讀檔案的十六進位，來判定它是什麼。

如果模型沒有這個能力，則需要手動整理出 JAR 內所有檔案的頭部供其推理。

Python3

對於 AI 而言，Python 是最棒的語言。

主要用以：

  • 拆包 & 重打包；
  • 生成 & 回寫中文字庫；

LLVM

確定了關鍵的邏輯鏈路後，是時候開始修補二進位邏輯了。

主要使用三個工具：

  • clang：把 ARM Thumb 匯編編譯成目標檔；
  • ld.lld：按照遊戲中的實際地址排列這些程式碼；
  • llvm-objcopy：把需要的機器碼單獨取出，交給 Python 寫回 binary.mod。

如果缺乏 IDA 做逆向，LLVM 也是一把不錯的好手。

工具就到此為止。

畢竟這個章節是寫給 AI 看的，而不是給人類（嘆息）。

Hack 吧！

正式開始漢化吧！

漢化方略

這裡先拋棄它是 WIPI 遊戲的事實。

究其根本，絕大多數遊戲，漢化的思路都是相通的：

  1. 研究語言包調用鏈
  2. 提取語言包
  3. Hack 語言包調用鏈
  4. 語言包回打測試
  5. 翻譯語言包
  6. 製作位圖字庫
  7. 正式回打
  8. 回歸測試，必要時重新執行 5-7

逆向方略

二進位逆向看似難，但只要抓住關鍵，同樣可以令 LLM 漂亮完成任務：

在遊戲裡擷取關鍵字符串，層層推進，找到共同調用點。

語言包

本遊戲共有五類字串：

  • dat/talk0.gtr ～ talk3.gtr：劇情，事件對話
  • dat/*.giu：道具、技能、提示、介面文字
  • dat/q/q*.giu：任務
  • dat/*.str：其他文字
  • binary.mod：其他文字

檔案各不相同，結局卻只有一個：它們最終都會匯聚到 binary.mod 這個塊中被調用。

設計字庫

使用 LLM 繼續追索，會發現遊戲準備了 8 個字庫槽。

因為韓文和中文在編碼和形體方面的相似性，這簡直再適合不過。

我們計劃使用位圖字庫，因為沒有什麼比位圖更加 自由，可控，美觀。

在 QVGA 螢幕下，最佳的字號是 12Px，這裡選擇最棒的 Fusion Pixel 12Px。

前文說過，遊戲準備了 8 個字庫槽，正好，可以將字庫設定為 8 張 384x192 的圖像（32x16）。

共計 4096 個字體槽，前 95 格留給 ASCII，剩下的可以全部留給中文。

繪製中文

理論很美好，現在該實際 Hack 操刀了。

Fusion Pixel 12Px 的字元寬度為『中文 12Px』『ASCII 6Px』。

因此， 0xF048 可 Hack 為『中文 + 12』『ASCII + 6』。

0xF130 呢？則讀取兩位元組字號，換算字庫位置，畫出對應的字形。

最後，由 0xB940 來統一將文本繪製到螢幕上。

其他方面，就無須我們過多操心了。

因為我們只是見縫插針，而不是大刀闊斧的砍掉整個渲染鏈路重寫。

0xB940 會忠實的對位圖字庫進行顏色控制。

此乃『循根』也。

換行策略

字能夠完成繪製，一款粗製濫造的『漢化』垃圾就已經完成了。

Why? 中文在 QVGA 下的最佳字形大小為 12PX。

韓文呢？是 10Px，ASCII 則是 5PX，這款遊戲也是如此。

若遵循原版的寬度計算換行邏輯，則字體的右溢出終究成定局。

如：若一個介面的 行容量 為 20，則該行寬度即為 20 × 5PX = 100PX。

在『選單』-『技能』的『技能簡介』中，中文可以正常顯示，但字元滾動時，卻溢出了小面板。

給出技能文本，令 LLM 追索，可知：

這也是這個小面板中技能文本上下越界的原因。

早先我們將 0xF130（文字繪製函式）Hack 為了中文渲染邏輯，決定上下裁切的函式也被誤殺了。

在重寫 0xF130 時，恢復原版的相關判斷即可。

語言包提取

繪字的邏輯解決了，現在，是時候一窺語言包本身了。

好吧，放在這裡並不合適……或許應該放在正式研究繪製邏輯之前？

因為 LLM 的緣故，語言包的解析變得毫無技術門檻，因此這個章節就簡單一筆帶過吧。

令 LLM 提取韓文，結果輕鬆寫意：提取腳本飛速落成，資料條目井然有序，完美！

嗎？

資料提取真的完整嗎？

這是開始漢化前最重要的測試環節：一字不譯，原樣回打，二次匯出。

二次匯出的內容，應當和一次匯出的內容逐字元一致；反之，則需重新研究匯出腳本。

邊界處理：語言包解析

該遊戲的 .giu、.gtr 有一個反人類的偵錯誤區：檔頭地址表記錄的並非『絕對位置』，而是『相對於當前表項末尾的距離』。

地址表中，每個格子（表項）固定佔用 4 bytes。

當我們讀完第 i 個格子時，檔案指針已經走過了 4 × (i + 1) 個 bytes。

我寫到這裡覺得無比抽象……光說不練假把戲，就現場拆一個 tip.giu 吧：

按小端序理解，可知：

故：第一筆位置 = 從第一格末尾（4 bytes），再往後 + 224 bytes

故：第二筆位置 = 從第二格末尾（8 bytes），再往後 + 274 bytes

以此類推。

粗翻一次，打開遊戲，系統選單中，頂部的『技能』標題文本空空如也。

令 LLM 追索：

對應：

LLM 初步編寫的程式只認 00 開始+結尾 的完整字串，它只能看見 길드보유스킬。

不過，스킬 這種從母句中間開始、卻共用同一個結尾 00 的字串，會被直接略過。

漢化回打時，母句被翻譯為『已有公会技能』並搬至新地址，原位址被清空——主選單的指針卻依然留在 0x77C94，讀到的自然是嘛都沒有。

我非常不想把一個小章節寫的如此羅嗦，但還有一種務必要寫出。

수（0x78540），也被單獨使用了。

화 火，풍 风，지 地，수 水。

水？保存？？好吧，你贏了。

嘆罷，只覺 LGT 鬼劍士 那樣的『筆畫拼字』，也不是不可以接受了。

該收尾了。這是如何處理的？

每一個遊戲情況都不一同，因此也只能對症下藥。

核心思路只有一個：忽視字串，讓 指針 說話。

這個方法是 LLM 給出的。因為到了這裡，我的腦細胞幾乎已經被榨乾了，無法進行更多思考orz：

  1. 遍歷遊戲執行檔中所有的記憶體指針，研究它們指向了字串庫的哪個位移；
  2. 若發現有指針 精準插在母句之間，將該片段判定為獨立實體，強行剝離提取、翻譯；
  3. 漢化回打時，為所有被提取的文本分配 獨立地址，並將原本中途攔截的指針重新指向新地址。

這個方法有一個前提：遊戲內的文本地址 必須是靜態。

幸運的是，效果很好。

我實在不理解，開發團隊為什麼要節約這三瓜俩棗，純屬添堵。

是的，被拆出來的文本也只有十幾個而已……TND。

性格總結

鑑於可能造成劇透的原因，在背景方面，僅整理一代。

大部分的角色實際上沒有什麼好整理的，注意他們的種族，立場和措辭即可。

至於只有一兩句台詞的路人……知道就夠了。不必請 LLM 額外送他一份人生理想。

傑克

一/二代主角。

因帕普尼利帝國致使其家園毀滅，因而加入克萊普的『雷霆傭兵團』；後投身阿里格斯軍，單槍匹馬覆滅帕普尼利帝國完成復仇。

  • 性格：冷硬果斷；對敵人無比殘酷，對平民與求助者仍保有責任感。

  • 語言風格：簡短，常用省略號、括號內心獨白與冷笑；戰鬥時直接、訥諷、威嚇，做支線時多用「知道了」等簡潔的回應方式。

魯索

阿里格斯近衛騎士團長，傑克加入阿里格斯後的直屬軍官。

  • 性格：好戰、直率、忠誠、極度欣賞實力。

  • 語言風格：軍令口吻，句子高亢、催促性強。二代退役後，語氣變得隨和。

吉普

傭兵團成員、傑克舊友。

與克萊普、露西亞長期行動，多次挑戰傑克落棧，又在終戰前用比試拖延時間配合救援。

二代的核心角色之一。

  • 性格：愛吹牛、貪報酬、怕死、滑頭，也是喜劇擔當；二代中被嫉妒衝昏了頭腦。

  • 語言風格：口語化強，常『嘿嘿』『切』，愛談錢、吐槽、誇口。

露西亞

傭兵團成員，傑克舊識。

早期與傑克關係親近；傑克退出後仍擔心他，曾救下吉普並勸傑克回團。

二代的核心角色之一。

  • 性格：機靈、會撒嬌、表面嬌弱，內有行動力；對傑克有特殊關心。

  • 語言風格：帶有調侃和撒嬌色彩，情感場景句子更猶豫和委婉。

科琳

山賊襲擊後的倖存少女，被傑克救下後留在傭兵團。

二代的核心角色之一。

  • 個性：膽怯、溫順、重情，關鍵時刻有勇氣。

  • 語言風格：大量省略號與敬稱，常用道歉、感謝、擔心等柔弱謹慎的情緒詞。

尼爾

高等精靈族族長，菲利普一世時代的核心謀士。

一代中，他把傑克視為重建帕爾卡斯帝國的關鍵力量。

  • 性格：冷靜、戰略性強、識人且現實。

  • 語言風格：正式、理性、長句多，常以因果推演表達觀點。

菲利普二世

菲利普一世身後，二世即位。

對先皇留下的平等政策不滿，意圖復辟貴族統治。

二代的核心角色之一。

  • 性格：傲慢，階級意識強，性格較為強硬。

  • 語言風格：上位者口吻，少有商量意味，冷硬而有距離感。

校對準則

  4. 建立全角色性格表
  5. 根據性格表，令 AI 二輪翻譯

BUG 2：等級差判定

上文提到，若玩家等級大於『2M + 10』，則經驗衰減。對應的函式為 0x275A2。

假設玩家現在 Lv.10，擊殺的怪物也是 Lv.10，按照公式可計算：

10 - 2 x 怪物等級（10）= 負 10。
負 10 <= 10
成立，不進入經驗衰減

前文一直都在說『某函式跳轉到某函式』，可它是如何跳轉的？

在 ARM / Thumb 中，一般使用 BLS 和 BLE 作為條件跳轉指令。

唯一的區別在於，BLS 是『無符號』判斷。

在 CPU 裡，數值本身沒有『正 / 負』，只有一串 32 位元的二進位。

例如，-10 在用 32 位元二進位保存時是『11111111 11111111 11111111 11110110（0xFFFFFFF6）』。

修復方式非常簡單，改成 BLE 即可。

不過也不能不做，我們可以在 0x2F924 前，再增加一次獨立的隨機判定：

兩次判定彼此獨立，雖然不優雅，但是省心。

現在，卷軸的掉率是 9.0% 左右，略低於藥水，也不會造成溢出。

裝備錯峰

什麼是裝備錯峰？這需要先聊遊戲的屬性成長機制了。

遊戲中，提升實力有三種方式：屬性加點，技能加點，更換裝備。

前兩者和升級強綁定，且加點提供的屬性抑或技能增強（按照百分比增強技能），只有到遊戲 後期 才能體現。

因此，唯一的途徑變成了更換裝備。

裝備的更換也不是有錢就可以的，它和等級強綁定。

即便我們修改了經驗公式減弱了肝度，裝備更換窗口期又何其漫長？

角色在面對同級甚至低幾級的怪物時，只有嗑藥才能維持健康的 HP 線。

幸好，在一個窗口期內，遊戲為每一個身體部位的裝備都準備了四檔；其售價和所提供的屬性成正比，無附加效果。

如果，我們能將前三檔裝備的所需等級適當調低，是否可以解決這個問題？

如果修改……

裝備資料位於 dat/item.gir，每筆資料 24 bytes，+0x10 便是裝備需求等級。

改吧！

現在，原本擠在同一個等級的裝備被拆開，升級過程中便常有新裝備可以更換了。

你說缺少金幣？有好好做支線嗎？因此這絕不可能 :)
